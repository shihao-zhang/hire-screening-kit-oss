# 方法论:HM + AI 协作的两层筛选漏斗与数据飞轮

本文是 kit 的"为什么这样设计"。代码会过时,这里的判断依据不会。

## 0. 一句话架构

**规则层管排序与召回,LLM 层管语义,人管决策**;三者之间用**标签回流 + 回归护栏 + 人在环归因**连成飞轮。

```
全量投递 ──规则粗排(可解释,可回归)──▶ 排序 + 精读网圈选
精读网   ──LLM 按 rubric 精读(语义)──▶ 两层结论 → HM 工作表
人工评估/面试进展 ──回流──▶ 标签库 → 护栏 → 归因队列 →(人拍板)→ 规则/rubric 修订
```

## 1. 为什么是两层,不是一层

- **纯规则**读不懂细分场景:关键词全中但实际做的是别的领域,是规则层的结构性盲区(实测反复出现)。规则只能数词。
- **纯 LLM** 全量精读贵且不可回归:改一版 prompt 无法证明"没把上一版对的判错"。
- 分层后各取所长:规则层**不追求聪明,追求可解释、可复现、可回归**——它的产出(分项分/flag)同时是 LLM 层的输入证据与归因的定位坐标。LLM 层只处理规则读不懂的判断:方向对口、经历真实性、owner 还是执行者。
- 成本结构:精读网约占全量 1/3,LLM 成本只花在有希望的候选人上。

## 2. 规则层设计原则

1. **经历权重 = recency 衰减 × ownership 语言信号**。应用层范式变化快,近期经验更值钱;"协助/维护"挂靠大厂不该享受大厂分。衰减设下限——不因一次转向折掉全部积累。
2. **防 gaming 是一等公民**:ownership 用"是否出现"不用出现次数(防堆砌"主导/从0到1");"自我评价/核心技能"小节整段截断不进语料(自陈是美化高发区)。
3. **劣化信号族的处置分三档**,判据是外部证据强度:
   - 证据强且精度高 → 乘数惩罚(如 AI 断档、传统企业无硬深度);
   - 证据有但会误伤 → 只标注 + 面试验证提示(如 owner-vs-执行,自陈词会骗过正则,语义判断交给 LLM);
   - 行业常态被误判 → 修口径(实习不计任期均值;项目制职业的短任期是行业属性不是跳槽)。
4. **复现性是硬约束**:评分基准日期显式固定在配置;整数月比较消除浮点边界翻档。"同一个人今天跑和明天跑分数不同"是 bug,不是精度问题。
5. **名单匹配短名必锚定**:两字缩写用前缀锚定,上线前全量扫命中详情——子串撞车这类 bug 会在一轮内踩两次。

## 3. 精读网:阈值网 + 近期放宽 + 召回子句

- **不用固定 TopN**:池子增长时 TopN 会把优质候选挤出网,分数阈值不会。
- **近期放宽**:给近 N 天投递更低门槛——新投递的时效价值高,漏掉的代价大。
- **召回子句**(强背书 + 规则拿得准方向):为"分项被埋但真实力强"的终点真阳性设计。教训:子句是拿已知锚点归因设计的,它让锚点进网是**按设计生效**,不是泛化证据;泛化只能等设计之后新产生的终点样本检验。
- 扩网提召回但线性推高精读成本,精读网覆盖率是要盯的成本指标。
- **⚠️ 「近期放宽」的基准日冻结了就要每轮对表,否则它会悄悄放宽**。为复现性(同一份档案今天跑和
  明天跑必须逐字节相同)把「今天」固定成配置里的一个日期是对的,**但固定不等于不动**:实测冻结
  8 周后,「近 21 天」这条子句的实际语义变成了「近 8 周」,精读网多留了 37 人而没人察觉——
  基准日不动时,**所有晚于它的投递都落在窗口内**,近期放宽退化成"永久放宽"。
  同一个冻结基准还喂着任期算术,不对表会把所有在职段的任期少算漂移的月数。
  做法:**开轮第一件事就是对表**,并按改规则的纪律走(模拟不落盘 → 血范围看精读网进出 →
  落地后与模拟 diff 逐字节一致)。对表本身会让人出网,先确认出网者是否都已有判定、有没有终点真阳性。

## 4. LLM 层纪律

- **rubric 是校准产物,不是先验清单**:每条都应来自真实人工评审/面试反馈的归因(写法见 RUBRIC-GUIDE)。
- **档案隔离**:LLM 只读进网者的结构化档案(dossier),不接触全量简历库;大批量走 subagent,主上下文不被简历文本污染。
- **批次 first-wins + 显式 override**:修正批放最高优先;历史批次永不删除。
- **重跑 ≠ 改进**:全体重评会静默劣化个案(把原本正确的扣分理由抹掉)。劣化哨兵盯"终版推荐且 red_flag 空、但历史版本曾有 flag"的人,列观察名单供人工复核——只提示,不自动改判。
- 批次结果全部落文件,合并器可随时全量重放——LLM 结论也要可回归。

## 5. 数据飞轮:标签分层与人在环

- **标签分层**:人工评估 ∪ 终点真阳性 = PRIMARY(强基准);面试结论 = REFERENCE(面试官宽严方差大,只做分离度参考,必须附每面试官通过率);阶段流转/撤回 = WEAK。**"触达未回复"不是负标签**——候选人从未表态,混进负样本会教系统压低没被联系过的人。
- **归因人在环不可让渡**:归因队列只报现象 + 事实分类 + 维度定位,**不提规则改动建议**;改什么由人拍板。这不是效率妥协——规则改动是雇佣标准的变更,责任必须落在人身上。
- **触发保持手动**:编排器只在操作者在场时跑,不挂 cron。写外部系统的动作逐轮授权。
- **内部记录排除**:staff/HM 本人的历史记录混入候选池时,候选人身份不计标签(否则污染终点集),面试官身份的数据照常统计。

## 6. 验证方法论(改规则前后怎么做)

1. **模拟不落盘**:改动先在副本上跑全量,并验证能否复现基线——这一步抓出过靠读代码发现不了的隐藏 bug。
   **并且要验证"模拟真的读到了模拟产物"**:实测 `harness.py` 曾忽略 `--out-dir` 只读正式 `out/report.csv`,
   于是护栏全绿其实是旧版本的绿。判据:模拟出的精读网人数必须与 diff 脚本算出的一致,对不上是读错文件,
   不是"改动无影响"。
2. **血范围量"谁被人看到"**:看精读网进出名单,而不是"多少人分数变了"——后者会吓退正确的修复(几十人分数微动但只有一两人真正进出网)。
3. **回归护栏(harness)**:一致率拆**规则层 vs 两层系统**双口径(差值=LLM 层价值);终点真阳性召回也拆两层(粗排埋没 vs 系统漏交付,后者才是交付口径);分布健康度防塌缩/饱和;版本 delta 逐人可解释。
4. **循环引用防护**:人工评估是调参样本,与规则可能共享盲区——一致率高≠预测有效。**唯一无污染的效度信号是终点真阳性召回**,且新设计的召回机制只能拿设计之后的新终点检验。
5. **已决策接受的漏网降级为 WARN**:护栏区分"新警报"与"人已拍板接受的已知情况",否则狼来了。
6. **别在圈选网内部测特征有效性——那里必然测不出东西**。实测:拿 83 条 PRIMARY 标签
   (人工评估 ∪ 终点真阳性 ∪ HM 面试判定)对七个规则维度做置换检验,**全样本无一显著**
   (最强的学历 p=0.073);只看 HM 面试子集(n=51)时**连方向都散掉**(学历差 -0.1、p=1.000);
   只有人工评估子集(n=22)里学历显著(+11.3,p=0.006),而那个子集正是调参样本、有循环引用。
   标志位(执行者主导/短任职/浅环境/AI 断档/冗长档)同样全部不显著。
   **这不是特征没用,是样本构成决定了测不出来**:标签只存在于"已被系统选中去面试/评估"的人身上,
   而选中与否正由这些特征决定——特征方差在标签子集里被系统自己压掉了。
   推论:**任何「用现有标签调特征权重」的方案都缺乏依据**,那等于拿系统自己的选择结果
   去确认系统自己的选择。
   要拿到无污染的特征效度信号只有一条路:**给圈选网外的人也打标签**——从网外抽 N 人
   请人评估,构成跨越圈选边界的校准样本。成本是人要读一批本来不会读的简历,但这是唯一
   能打破内生性的做法(与 LTR 的选择偏差是同一个问题的两面)。

7. **人工反馈用「你的特征里根本没有的理由」推翻你时,不要调权重,要把那个信号加到语义层**。
   实测:两条人工评估同时推翻 LLM 的「待定」,理由分别是「同为企业生产力赛道的创业团队」
   和「前沿公司加权」——LLM 压分用的都是**时长**,而人看的是**公司在不在这条赛道上**。
   规则层的公司维度只分大厂档位、**不分赛道**,这个信号七个维度一个都没编码。
   三种处理里只有第三种站得住:
   (a) 调现有权重——**没依据**(见上条:圈选网内测不出特征有效性);
   (b) 加一个规则维度——加维度必须重配权重,又回到 (a) 的无依据;
   (c) **加成一个 dossier 标记喂给精读层,不进评分**——语义层本来就是干"规则读不懂的判断"的,
       加标记不动分数、不动排序,血范围可验证为**逐字节零变化**。
   落地要点:①名单口径**要窄**,只收"主营就是这个"的公司,不收大公司里的一条业务线、
   不收自建自用——否则会与"传统企业 AI 深度存疑"那类判据**正面打架**(那正是它要压的形态);
   ②写明**只作正向证据、反向不成立**,名单必然不全,不在名单不构成负向;
   ③判据落地后要**逐条应用到所有可能受影响的人**,但**已有人工标签的人不改判**——
   那是拿标签反向拟合。实测 11 人受影响只改判 1 人,其余的阻塞点(归因链存疑、工具名美化)
   与新判据无关,**新判据不该用来盖过独立的反对理由**。

8. **一个参数别同时当「分数强度」和「标签阈值」用——改前者会静默改掉后者**。实测:
   `top_school = school_w >= 0.9` 把学校档权重同时当成(a)总分乘数强度与(b)名校/强校标签阈值。
   于是为拉大档间差距把 T2 权重从 0.9 调到 0.80 时,**全部 T2 学校静默从「名校」降级为「强校」**
   ——而这个标签是 LLM rubric 的输入(背书=无→verdict 封顶、=强校→不给高分),
   等于改一个排序参数顺带改了语义层的判定口径,且没有任何报错。
   实测规模:「名校」113→41、「强校」75→147,涉及 72 人的 rubric 门槛。
   **修法**:标签按**档位序号**判定(`tier in (1,2)`),权重只管分数。解耦后权重可自由调、
   标签分布逐档稳定。**排查线索**:调一个纯分数参数后,如果人群标签分布也变了,就是这类耦合。

9. **「拉大头部差距」是压尾不是抬头,代价要先量在纸面上**。乘数带宽是零和的:
   floor 从 0.90 降到 0.70,顶档乘数不变(仍是 1.0),变的是**无背书者从 0.90 掉到 0.70**。
   所以"给头部加权"的真实含义是"把没有背书的人压下去",必然收缩精读网。
   落地前至少量三件事:①**北极星(终点真阳性的系统召回)**——实测最激进的一档会把一位
   已走到「待入职」的人挤出精读网,召回从 11/12 掉到 10/12,**这是硬上限**;
   ②出网者是否都已有判定(已有则不漏读,只影响下一轮同类人);
   ③分布健康度——拉大差距会让分数摊开,实测峰档占比 36.1%→25.9%,排序区分度是变好的。

10. **护栏是单向的——它抓塌缩,不抓「还有余量」**。峰档占比 36% 在「<50%」的阈值下是 ✅,
    但 36% 意味着三分之一的人挤在 5 分以内,区分度很差;改造后降到 25.9%,这个改善**在旧指标
    体系里根本没有名字**。阈值是为了防止分布塌成一坨而设的,它不会告诉你分布可以更开。
    对策:给区分度一个正向指标——总分对 PRIMARY 标签的**标准化效应量**,跨版本追踪。
    实测它在改造前就是 0.372,改造后 0.487;**它本该在改造之前就显示"还有余量"**。

11. **「维度不显著」≠「结构没问题」——别把对错误问题的正确回答当成结论**。置换检验问的是
    "学历分/公司分能不能区分正负样本",答案是不能;由此推出"不改权重"是对的,但推出
    "评分结构不用动"就过宽了。档位改造动的不是跨维度权重,是**维度内部的档间距与乘数带宽**,
    这个假设没人提出来,所以没被测。事后配对检验(同一批人、同一批标签、只换口径)显示
    p 从 0.082 降到 0.021、效应量 +31%——**改结构产生了改权重产生不了的显著性**。
    写结论时把范围说准:是"跨维度再平衡无依据",不是"评分体系无优化空间"。

12. **参数扰动是最便宜的耦合检测器**。`top_school = school_w >= 0.9` 这类把一个参数同时当
    「分数强度」和「标签阈值」用的耦合(§6-8)潜伏了几十个版本,因为**从没有人动过那个参数**——
    飞轮每轮跑的都是当前配置。判据很简单:**扰动一个纯分数参数后,如果人群标签分布也变了,
    就是耦合**。建议作为飞轮的周期性步骤:对每个配置标量做 ±扰动、只模拟不落盘,输出
    北极星 / 精读网 / 分布 / **标签分布**四个 delta。最后一项抓耦合,前三项顺带产出"哪个参数还有余量"。

13. **规范输入与实证输入要分开接**。"头部应该更值钱"是一句**招聘政策**,不是一个数据事实;
    对它说"没有数据依据"是用实证的尺子量规范的命题。飞轮目前只有一条人→系统通道——逐候选人
    的【通过/不通过】标签,政策级的声明必须由人手工翻译成参数假设、跑模拟、找北极星上限才能
    落地。正确的处理顺序是:**先把政策声明翻成可测的参数假设,再用数据量它的代价**(§6-9),
    而不是先问它有没有数据依据。

## 6.5 指标体系:声明北极星,并确认它有没有分辨力

**先声明再优化**。没有声明目标的系统会退化成"靠判断拍板 + 一堆看着像目标的护栏"。

推荐分层(某实例的实际取法,新实例照此填):

- **一级 北极星(唯一优化目标)**:`终点真阳性·系统召回 @ 精读网覆盖率`。
  必须**成对**——召回单独最大化的平凡解是"全池精读",覆盖率是成本约束。
  它是**验收指标不是日常指标**:终点真阳性通常只有个位数,饱和后对单次改动零分辨力。
- **一级-先行(日常拍板看这个)**:`规则-LLM 边界方向一致率`——规则改动把某人推进/推出精读网时,
  该人已有的独立 LLM 判定是否与移动方向同向。**每次改动必然产生边界样本**,分辨力最高。
  ⚠️ 效度前提:只在改动**独立于 LLM 输出**推导时才算证据;拿它调参即自证失效。
  ⚠️ **判定必须早于改动**:实现上不能读「当前」LLM 判定——本轮新进网的人往往**本轮才精读**,
  那条判定产生于改动之后,算进去就是循环自证(实测:词表改动把 2 人推进网、同轮精读后
  指标报 2/2 全同向,而那两条判定正是改动之后写的)。正确做法是拿**上一轮结束时的
  verdict 快照**当「已有判定」的唯一来源,本轮新产生的一律不计入。
  ⚠️ 它是**调查触发器不是判决**:反向个案要逐个查,实测查出来是正确修复的情况。
- **二级 护栏(不优化,不能破)**:分布健康度、一致率不显著下降、复现性、覆盖率(成本闸)。
- **三级 诊断(定位问题,不拍板)**:规则层召回与系统召回的**差值**(变大=规则层在退化)、
  参考层分离度、LTR 水位。

**同时要写下不优化什么**:不优化精度/准确率(LLM 层做过滤,误召代价远小于埋没,这是两层架构
的直接推论);不优化一致率最大化(与规则共享盲区,冲高即过拟合)。

**必须落台账**:harness 每轮追加一行到 `out/metrics_ledger.jsonl`(`--version` 标注版本)。
单次快照看不出某个指标有没有分辨力——实测一天六个版本里,终点召回连续 5 版纹丝不动、
一致率一直持平,真正在动的指标当时根本没被记录。**只记不判**,台账是给人读趋势的。

## 6.6 词表回流通道:名单不冻结,但引擎仍确定性

公司/学校/专业这三维靠**手工名单 + 字符串匹配**,名单一冻结就必然落后于长尾——实测某池
1123 家去重公司里 **69% 任何名单都不认识**,865 段经历吃兜底分;新一轮投递还会持续带来新实体。

`core/vocab_reflux.py` 把这件事做成每轮的固定动作:

    --mode extract   捞出"本轮新出现且名单未识别"的实体 → out/vocab/pending_*.tsv
    (人/subagent 对 pending 做**事实归类** → **逐条人工复核** → 手工补进配置 TOML)
    --mode mark      记账(无论采纳与否),下轮不再重复提议

关键是**LLM 不进评分路径**:它只在这个工具里产出候选清单,人核定后写进配置,引擎照旧只读配置。
复现性、人在环、可审计三样都保住,而名单是活的。

**LLM 可信边界(实测,别高估)**:
- **高置信可用,中低置信必须人过**——某轮 850 条公司归类里 high 只占 3.5%,medium 档混进大量
  错判(教培/车企/金融/医疗被标成"知名科技公司")。
- **需要精确世界知识的事实不可信**——让它标学校 QS 排名档,8 所里错 4 所。
- **结构性事实可信**——中外合办 / 独立学院 / 校名易混 / 这个专业属于商科,这类判得准。
- 一句话:**LLM 做分诊不做决策**。价值在把 1123 收敛到 107 让人能看完,不在替人定档。

**档位是招聘 bar,不是事实**——LLM 可以说"这家是知名互联网公司",但它算 tier1 还是 tier2
只能由人定。补完配置照样走「模拟不落盘 + 血范围 + harness」再落。

## 7. 校准循环(一轮怎么走)

人工评估回流 → 归因队列按事实分类(硬分歧/网外漏召/面试下游/一致/格式待确认/终点漏网)→ 人逐条消化、拍板改或不改 → 改动走 §6 验证 → SPEC 记 changelog。原则:**n=1 不改规则**(防过拟合),记录形态、攒样本;LLM 层先兜底。

### 7.1 飞轮的设计边界:它防劣化,不提假设(一次复盘)

回看连续七个版本(v6.30–v6.36)的改进来源,**没有一个是飞轮自动输出提出的**。全部来自三个飞轮
之外的通道:①HM 的 bar 声明(档位改造、赛道同构性);②陪跑的 AI 助手在跑轮次时的顺手观察
(别名漏判、基准日漂移、标签与权重耦合、词频标志位七次失灵);③个别人工标签的反向信号
(两条「同赛道公司」理由推翻待定 → track_peer)。

飞轮把它被设计去做的事做得很好——防劣化、保复现、拦坏改动、把分歧摆到人面前;但它**没有一步
是在"提出改进假设"**。最典型的一例:三位双背书的终点真阳性连续多轮被印在 harness 表里标
「✗埋」,数据完全可见,可归因队列只对人工评估的分歧做归因、不对终点漏网做归因,于是
"这几个被埋的人全是双背书、被 10pp 的乘数带宽困住"这个模式,直到 HM 提出要给头部加权才被算出来。

**把飞轮从"摆现象"推到"提假设"的路径**(按便宜→根本排):

| 步骤 | 做什么 | 会抓到什么 |
|---|---|---|
| 终点漏网归因 | 对每个 rank 落在前 40% 之外的终点真阳性,算哪几个维度拖的、被埋者之间的共性 | "全是双背书却被埋"这类模式第一轮就报出来 |
| 区分度指标 | harness 加总分对 PRIMARY 标签的标准化效应量(§6-10) | 在改造**之前**显示"还有余量" |
| 基准日陈旧告警 | 评分引擎启动时若基准日落后当前日期 >N 天则告警(§3) | 8 周漂移会在第 3 周被看见 |
| 参数敏感性扫描 | 周期性对每个配置标量 ±扰动、只模拟(§6-12) | 耦合缺陷 + 哪个参数还有余量 |
| 网外抽样打标签 | 每季度从网外抽 N 人请人评估(§6-6) | **唯一**能拿到不带选择偏差的效应量的路 |

**实测回报(上线首轮)**:终点漏网归因上线的第一轮就报出「5 位被埋终点真阳性全被年限维度拖分」。
顺着查下去不是曲线设计问题,而是**源侧年限字段缺失时一律给兜底分**——19% 的人缺该字段,其中含
14 年大厂经历与名校硕士毕业后已工作一年的终点真阳性。模拟两种补法后人拍板「只用工作经历推算、
没有非实习经历仍按缺失」,落地后规则层召回 7/12→9/12、区分度 0.487→0.542。
注意这次提升里包含触发修正的那几个人自己,不能当独立效度证据;修正的理由是数据 bug 本身。
**一般化**:任何「缺失即兜底」的维度都是潜在埋人点,新增维度时就该问一句"缺失时怎么办、缺多少"。

**什么不该自动化**:落地任何规则改动、档位/名单的 bar 决策、"要不要拉大头部差距"这类方向选择。
飞轮的正确形态是**每轮多问几个"为什么",把假设和血范围摆到人面前,然后等人说"同意"**——
它该做的是带证据地提出,永远不是决定。

## 8. 已知边界

- 关键词读不懂场景,规则层永远有语义盲区——这是两层架构的前提,不是待修的 bug。
- 面试结论受面试官方差污染,永远只做参考。
- 系统一致率的上限是人工评估的质量与格式纪律(评语按约定格式开头,才能自动归类)。
- 术语词表与公司名单会随行业漂移,双维度同时不在名单的真 builder 是已知埋没形态——靠精读网召回子句与人工兜底,并定期把新术语/新公司补进配置。

## 9. 特征侧盲区:先榨干源侧结构化字段,再自造正则

规则层最贵的 bug 不在权重,在**特征抽取**。实测教训:

- **自造正则 vs 官方字段**:靠 title 正则判"这段是不是实习",全池只认出 56%(官方 `career_type` 标实习 391 段、
  正则命中 219 段),漏掉的 172 段一次污染任期均值、短任职计数、大厂背书三处。源侧结构化字段是免费的 ground truth,
  **能用字段就别用正则**。
- **但采用前要验证枚举**:不盲信字段名。用分布特征自检(实习段中位 4 月/81%≤6 月 vs 全职段中位 20 月),
  再看它与旧口径的重合率(正则命中的 221 段里 219 段官方也是实习)。两项都对上才敢换。
- **官方字段也有缺,只作第二视角**:同一批数据里,985 高校的 tag_list 有空的。所以官方标签用来**交叉核对**
  自建名单、暴露漏判误判,**不能替代**它——自建档位是刻意设的招聘 bar,不是学校事实。
- **同一语义禁止两份名单**:两份必须一致却无一致性机制的名单一定会背离。实测一份"名校加成"名单与"背书档位"
  名单漂移到 58 所漏判、11 所误判(2 字中文简称做子串匹配撞车、3 字母 ASCII 键撞进无关英文校名)。
  发现即合并到单一来源。
- **字符串匹配的三条通用纪律**(名单类特征通用,不止学校):ASCII 键要**词边界**,CJK 键比**归一串**(去空白/分隔符),
  多键命中取**最长键**(更具体的压过更泛的)。短简称必须**前缀锚定**。
