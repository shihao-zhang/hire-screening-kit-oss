# 模型资源 ↔ 任务路由表

## 为什么要有这张表

管道里只有**精读层**调用模型，其余步骤都是确定性脚本。但「精读用哪个模型、复核用哪个模型」过去写在协议正文里，模型一换代就出现三种漂移：协议过期、新旧批次口径混用、出问题无法区分是模型还是提示词。

这张表把「任务 → 执行通道 → 模型/effort」抽成一份配置：**换环境只改表，协议只引用任务名**。

## 初始化时怎么填

1. 复制模板到私有实例：

```bash
cp <kit>/config/model_routing.example.toml ~/my-screening/config/model_routing.toml
```

2. 盘点本机可用的执行通道。常见三类：
   - `claude-session`：当前 AI 助手直接处理（规则设计、归因、文档、飞书交互、改代码）——**不需要另选模型**；
   - `claude-subagent`：开子代理并行评审；
   - `codex-cli` / `agy`：本机 CLI 调用其他模型家族。

3. 每个通道填 `kind`、`model`、`effort`；不确定模型 ID 时填 `"auto"`（用 CLI 当前配置）。

4. 核对 `[tasks]` 的默认映射是否符合你的分工；不用的通道留空。

## 默认任务映射

| 任务 | 默认执行者 | effort | 说明 |
|---|---|---|---|
| 探测/合并/评分/建档/同步/回读/护栏 | deterministic | — | **不调用模型** |
| 词表实体归类 | claude_subagent（轻量） | medium | 只归类、不定档 |
| 常规精读（dossier 批量） | codex_cli | medium | 批 10–12 人，见批处理准则 |
| 高分复核（推荐且 ≥80） | hetero_review | high | 全量、盲评、优先异构家族 |
| 边界复核（60–79 推荐/方向存疑） | claude_subagent | high | 抽 20% |
| 漂移监测 | codex_cli | medium | 每轮 5 份历史档案盲评 |
| 交叉模型审计 | hetero_review | high | 只出对照，不覆盖 |
| 规则设计/归因 | local_claude | 会话默认 | 人在环，AI 不替人拍板 |
| 文档/看板/飞书交互 | local_claude | 会话默认 | 写外部系统后必回读 |
| 改代码 | local_claude | 会话默认 | 非平凡改动走 external_review |

## 三条纪律

1. **未知任务不得自行选模型**：先在表里补一行再执行。
2. **换常规精读模型 / 通道 = 口径变更**：先按批处理准则第 5 条盲评 5 份历史档案，分差中位数 >3 分就停线排查；不要在新旧模型之间直接续跑同一批。校准结果落盘到私有实例 `out/calibration-<日期>.md`。
3. **模型 ID 不进协议正文**：协议只写任务名与批处理准则，具体 ID 以本表为准。
4. **同一家族不算异构**：高分复核要选与初评不同家族的通道；实例可以按供应商/账号约束排除某些通道（在本地表里删掉对应资源，并把引用它的任务改到别的资源）。
